# Искра 0.12.5 — сама подбирает настройки под телефон

Отчёт для владельца и других ассистентов. Предыдущий — [0.12.4](2026-11-05-0.12.4.md).

## Выпущено
RELEASE_ROW

## Зачем
Скорость модели на конкретном телефоне я до сих пор только оценивала — по ARM-серверу GitHub, с поправкой «в 1,7–2,3 раза
медленнее». И число потоков было угадано: столько, сколько у телефона быстрых ядер (у Redmi Note 14 — 2 из 8). Помогают ли
шесть медленных ядер читать запрос или только тормозят быстрые — зависит от телефона и модели, и заранее этого не знает никто.
Теперь это меряет сам телефон.

## Что сделано
1. **Замер в мосте.** `bench` читает 96 служебных токенов и пишет 16 — с теми потоками, что заданы, — и возвращает токены в
   секунду для чтения и для ответа. `setThreads` меняет потоки на лету (в llama.cpp они раздельные: для чтения многих токенов
   сразу и для ответа по одному).
2. **Подбор.** Пробуются: быстрые ядра, плюс два, все ядра (на Redmi Note 14 — 2, 4, 8), сначала короткий прогрев. Для ответа и
   для чтения выбирается своё лучшее; из почти равных (в пределах 5%) — меньше потоков: меньше нагрев, экран не дёргается.
   Итог запоминается для модели и применяется при каждой загрузке.
3. **Когда.** Сразу после скачивания модели («Подбираю настройки под этот телефон…» в карточке) и по «Проверить скорость».
   Итог — строкой в карточке и в журнале со всеми замерами.

## Проверено (запускалось)
- `ISKRA_CORE_ONLY=1 ./gradlew :core:test` — **238 тестов, 0 ошибок**. Новые: выбор кандидатов (2/4/8, 4/6/8, 2/4, 1); раздельный
  выбор для чтения и ответа, «меньше потоков из почти равных», прогрев перед замерами; ничего не измерилось — настройки не
  меняются.
- Настоящий llama.cpp на крошечной модели: замер возвращает скорость, `setThreads` меняет потоки (видно в описании модели),
  подбор проходит, и модель после замера отвечает.
