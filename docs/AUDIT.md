### Самые серьёзные проблемы прототипа
1. **Главной фичи нет**: нет персонажа поверх интерфейса — это продукт, а не чат.
2. **Слабый интеллект как единственный**: модель 0,5B — это потолок качества, который не исправить промптами.
3. **Невоспроизводимость**: нет исходников и сборки; нативный бинарник без исходников нельзя проверить.
4. **«Память» — это заметка, а не память**: без структуры, ранжирования и защиты от секретов.
5. **Хрупкие команды**: точное совпадение фраз; модель не может действовать.
6. **Характер по умолчанию** поощряет «ревнивые» паттерны — для массового продукта это риск
   (зависимость, манипуляции) и вероятная проблема с модерацией магазинов.

### Что сохранено из решений ChatGPT
Минимальная служба спецвозможностей без чтения экрана; честные формулировки («адаптация, а не
переобучение весов»); подсказка про «ограниченные настройки» HyperOS; позиция «приватность по
умолчанию»; проверка целостности импортируемой модели (пригодится для локального провайдера).

## 3. Архитектура

```
┌────────────────────────── Телефон (Android) ──────────────────────────┐
│  OverlayService (FGS specialUse)          UI (Compose)                │
│   ├ AvatarView ← AvatarBrain(core)         ├ MainActivity: чат/память/ │
│   ├ CatgirlRenderer (Canvas)               │  настройки/разрешения     │
│   └ облачко реплик                         └ QuickChatActivity (поверх)│
│            ▲ CompanionBus (эмоции, речь, «думает», «слушает»)         │
│  ChatController ──► CompanionAgent (core)                              │
│                     ├ CommandParser — офлайн-команды (0 мс, бесплатно) │
│                     ├ PromptComposer: границы → личность → стиль →     │
│                     │   настроение → память (как данные) → ситуация    │
│                     ├ MoodEngine / StyleFeedback                        │
│                     ├ MemoryManager → SQLite (локально)                 │
│                     ├ ToolRegistry → SafetyPolicy → AndroidTools        │
│                     │      (Intent, CameraManager, AudioManager,        │
│                     │       AccessibilityService: только глоб. действия)│
│                     └ LlmProvider ──HTTPS──┐                            │
│  Voice: SpeechRecognizer (вход), TextToSpeech (выход → рот персонажа)  │
│  KeyVault: AES-256-GCM в Android Keystore                               │
└────────────────────────────────────────────┼───────────────────────────┘
                                             ▼
                    Облако: любой OpenAI-совместимый API или Anthropic
               (MVP — ключ владельца; для массового продукта — свой прокси)
```

**Локально:** персонаж и анимации, офлайн-команды, вся память и состояние, политика безопасности,
хранение ключа, TTS (если установлен русский голос). **В облаке:** генерация ответа и выбор
инструментов (только при сообщении владельца), сжатие старого диалога в эпизоды.

### Ключевые решения и почему
- **Модуль `core` без Android.** Личность, память, агент, политика, поведение персонажа — чистый
  Kotlin. Это даёт быстрые тесты на ПК и возможность переиспользовать логику (iOS/десктоп/сервер).
- **Независимость от поставщика.** `LlmProvider` с двумя реализациями покрывает OpenAI, OpenRouter,
  DeepSeek, Mistral, Groq, собственный vLLM/Ollama за HTTPS и Claude. Модель меняется в настройках.
- **Эмоции через тег `[happy]` в начале ответа**, а не через особый API, — работает с любой моделью;
  отсутствующий тег не ломает ответ.
- **Память в промпте — данные, а не инструкции**: обёрнута в теги, `<`/`>` экранируются. Это
  снижает риск prompt injection через сохранённый текст.
- **Каждое действие проходит через `SafetyPolicy`** — и от модели, и от офлайн-парсера.
- **Персонаж нарисован кодом**, а не картинками: нет лицензионных рисков, APK маленький, любая
  плотность экрана. Интерфейс `AvatarPose` позволит заменить рендерер на скелетную анимацию (Rive)
  без переписывания поведения.

### Ограничения Android, которые нельзя обойти без root/ADB
- «Поверх приложений» и спецвозможности выдаются **только вручную** в настройках. На HyperOS для
  APK не из магазина спецвозможности сначала блокируются («ограниченные настройки»).
- Обычное приложение **не может** само включать Wi-Fi/Bluetooth/мобильные данные (Android 10+),
  звонить без подтверждения, читать чужие уведомления без отдельного доступа, нажимать кнопки в
  чужих приложениях без AccessibilityService с чтением экрана (в MVP сознательно не используется).
- HyperOS агрессивно выгружает фоновые приложения; даже с foreground-сервисом нужны «Автозапуск» и
  «Нет ограничений» — их можно только показать, но не включить программно.
- Голосовая активация «по имени» в фоне требует постоянного микрофона (foreground-сервис типа
  `microphone`, заметный расход батареи и строгие правила Google Play) — отложено.
- Google Play: AccessibilityService с `isAccessibilityTool=false` требует декларации и отдельного
  экрана раскрытия; `specialUse` FGS требует обоснования. Для личной установки (sideload) это не важно.

| Вариант | Качество (рус., характер, инструменты) | Задержка | Стоимость | Приватность | Сложность |
|---|---|---|---|---|---|

## 6. План разработки

### MVP (0.2.0-mvp, этот репозиторий) — рабочий APK
**Задачи:** оверлей-персонаж с анимациями и реакциями; чат (главный экран + быстрый поверх
приложений); облачная LLM с инструментами; офлайн-команды; память и характер (базово); голос
(системный); экран разрешений для HyperOS; хранение ключа; тесты ядра; CI.
**Готово, когда:** APK ставится на Redmi Note 14, проходит чек-лист `docs/TESTING.md`, персонаж
переживает час в фоне, команды работают без сети.
**Проверка:** `./gradlew :core:test` (сделано: 32 теста зелёные), ручной чек-лист на устройстве.

### 0.2 — характер, голос, память
- Нейро-TTS (облачный, с кэшированием) с «кошачьим» тембром; офлайн-распознавание (Vosk, русская
  модель ~50 МБ) как запасной вариант; потоковые ответы (SSE) — рот начинает двигаться через ~1 с.
- Память: векторный поиск (эмбеддинги, локально или через API), редактирование записей, экспорт в JSON.
- 👍/👎 к ответам; «дневник» эпизодов; рефлексия раз в сутки (сжатие эпизодов в факты).
- Управляемая инициатива: утреннее приветствие, напоминания (WorkManager), «соскучилась» после
  долгой паузы — с переключателями и лимитом частоты.
- Шифрование базы (SQLCipher) по желанию; биометрическая блокировка раздела «Память».
**Зависимости:** MVP, ручные тесты на устройстве. **Готово, когда:** латентность первого звука
< 2 с в Wi-Fi; память проходит набор сценариев «вспомни факт через неделю».

### 0.3 — устройство и навыки
- NotificationListenerService (отдельное согласие): «что мне пришло?», сводки, фильтр рабочих чатов.
- Календарь (CalendarContract Insert без разрешения на чтение; чтение — отдельно), контакты для
  «позвони маме» (READ_CONTACTS по запросу).
- Декларативные навыки + редактор; многошаговые планы с подтверждением всего плана.
- Rive-персонаж (профессиональный риг, 20+ анимаций), ходьба по краям экрана, реакции на
  открытое приложение (только имя пакета, без чтения экрана).
- Локальный LLM-провайдер (llama.cpp из исходников, подписанная модель, загрузка по запросу).
**Готово, когда:** навык можно создать без перекомпиляции; каждое действие видно в журнале.

### 1.0 — стабильный продукт для широкой аудитории
- Свой сервер-прокси: аккаунты, ключи на сервере (не в APK), квоты, биллинг/подписка, модерация,
  маршрутизация моделей по стоимости; телеметрия только с согласия и без текстов.
- Политики Google Play: декларации спецвозможностей и FGS, политика конфиденциальности, возрастной
  рейтинг; альтернатива — RuStore.
- Производительность: < 3 % батареи в час с персонажем на экране; холодный старт < 1 с; Baseline Profiles.
- Тесты: инструментальные (Compose UI), скриншотные для персонажа, нагрузочные для прокси; бета на 50–200 человек.
